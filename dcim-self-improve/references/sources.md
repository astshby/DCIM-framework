# Explicit reference roles

Configure authorized addresses privately. Assign each supplied file its actual
role, top/revision, purpose and applicability in the first task. The package has
no bundled PDK/compiler, mask rules, devices, generator or electrical models.

Useful source roles include independent circuit/netlist intent, native-device
reference, target-node PDK/decks/layer map/models, compiler macro, digital-flow
reference, composition/hierarchy reference and scoped experience. Required roles
and exact file sets depend on the selected stage and claimed checks. The
configuration's resource IDs and `stages` lists express those requirements.
An absent optional compiler does not block initial circuit authoring. A claimed
compiler comparison requires its actual matched boundary and supplied evidence.

Use exact authorized filenames in private configuration and recipes. Source
files stay read-only unless editing is explicitly authorized. Capture file hash,
source top, circuit provenance, observations and electrical limitations. A layout
extraction cannot silently become an independently authored source circuit.

A reference from another node can inform topology and organization. Its numeric
layers, pitches, model parameters, marker exemptions and qualification never
transfer automatically. Inspect target rules/models and the generated final
artifact. Compiler and custom-logic rule domains can differ on the same node.

Optional private initial recipes declare an explicit dependency closure in
`initial_recipe`. The initial code and instructions are copied into a new run.
Changing a root address alone does not port recipe geometry or imported helpers.
The historical technology-specific generators remain in preserved source/Git
history. They are outside this main package's active executable surface.

Obtain actual EDA runner APIs and tool documentation from the authorized local
installation or applicable installed skills. No host, scheduler, model ID or
licensed-data address is assumed by reusable code.
