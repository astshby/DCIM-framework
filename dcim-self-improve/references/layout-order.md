# Parent-constrained layout planning

## Physical dependencies

Establish independent circuit intent, target function, electrical conditions and
composition before layout. Inspect the supplied reference's actual hierarchy,
transforms, functional placement and access. Bind exact source/top/observations.
Read target-node rules and model coverage. A reference's geometry and electrical
qualification have separate evidence scopes.

Select the task's storage/compute grouping from its circuit and authorized
architecture. State capacity, operand identity and arithmetic width explicitly.
Measure legal repeat pitch, routed envelope, termination, TAP/body ownership and
accessible pin bands. Do not infer a universal grouping count or decoder fraction.

For a height-constrained compute block, organize its whole associated multiply/
access and complete arithmetic against the declared storage group and parent
band. Use functional height for legal packing/folding while measuring actual
routed width and loading. Primitive bboxes need not match. Functional rows,
mask/termination extents and route/PG envelopes require separate observations.
A routing-only tall bbox does not establish useful device-row alignment.

Measure a small connected block and its actual interfaces before committing to
costly expansion. Derive decode/control geometry and loading from the task's
actual architecture and parent access. Feedback can reopen an earlier assumed
height, width, source grouping or interface. Bounded parent probes can proceed
with named diagnostic gaps. Full qualification needs its applicable checks.

## Mandatory architecture admission

Physical task packets include inline approved hierarchy/order, independent
source/operand identities, transforms/facing edges and relevant arithmetic widths.
State parent W/H limits, common functional-row origins/heights/phases, straight
continuous intended PP/NP boundaries, TAP/body/termination ownership and routed
signal/PG access. Bind authoritative sources as mandatory resources.

Main checks proposed coordinates against that contract before construction.
A conflicting repair returns for an explicit architectural decision. Builder
reports actual generated hierarchy/transforms, functional rows, bands and body/
access witnesses separately from DRC/LVS. Equal all-mask height, zero implant
overlap and a single shared boundary establish limited observations.

At intended PP/NP interfaces require direct abutment without an artificial gap
or opposite overlap. Remove redundant context only with real legal powered
same-body service. Inspect source identities, rule domains, final transformed
masks and parent routing. If actual target rules conflict with the requested
organization, report the precise conflict and its evidence to Main.

Dimensions, fin/gate phases, numeric layers, device models, grouping counts and
exact compiler filenames belong to the private task/recipe. They remain bound
to their source and target applicability. Cross-node transfer is a hypothesis.
