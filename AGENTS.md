# DCIM framework instructions

Main is the preferred process-neutral improve-3-derived workflow. Read README,
`dcim-self-improve/SKILL.md` and the assigned role. Developer history stays in
HANDOFF and outside ordinary role packets. Private PDK/compiler/config/recipes,
models, runs and experiment data stay outside public Git/ZIP.

Main performs one actual initial-planning step and admits a bounded Builder task.
Use programmatic config/init/check/context preparation. A fresh task can start
with an empty design and no proprietary seed. Stage-required resources are
explicit. Comparison-experiment baselines belong to requested comparison tasks.

Builder owns ordinary implementation and diagnosed repair within the active
bounded task. Analyst consumes artifact-bound results, assesses qualification,
maintains scoped experience, writes actual concise reflection and proposes a
next executable task or closure. Main checks architecture, MUST constraints and
resource authorization. Failure and closure retain reflection. Ordinary repair
can reuse its mechanism. No separate mandatory Reflect dispatch is required.

Use actual supported model IDs and the available native agent API. Record actual
context isolation and agent identity. A new substantive task uses a fresh context
where supported. Main can perform bounded authorized work directly. Scripts
assemble explicit AI selections and never invent plans or invoke agents.

For physical work bind independent circuit intent, source/top identities,
parent W/H, hierarchy/transforms, functional rows/phases, intended straight
continuous PP/NP bands, TAP/body/termination ownership and signal/PG access.
Direct intended PP/NP interfaces abut without artificial gap or overlap.
Remove redundant TAPs only with real powered same-body access and applicable
rule coverage on the final artifact. Keep diagnostic gaps explicit. Source LVS,
DRC, function, ERC, electrical and complete parent qualification stay separate.
Do not transfer node-specific dimensions, rule exemptions or pass claims.

Use pinned run programs/instructions and exact input identity. Inspect actual
state and owned jobs before resuming. Reconcile uncertain submissions before
retry. Preserve original artifacts, executed code/dependencies, parameters,
prompts, checks, failed trials, experience, actual reflection and timing. Hashes
establish saved bytes. They cannot establish execution or physical correctness.

coarse/coarse_fine retain their original executable APIs and fixed-run semantics.
Do not upgrade historical runs or import the large legacy runtime into main.
Framework checks authorize no EDA, system/dotfile edits or unrelated job control.
Server Git commits are allowed. The user handles GitHub publication.

At development closeout obtain independent review, record experience and actual
reflection, run relevant software/package checks, update HANDOFF and external
handoffs, and commit. Package only the reviewed final main checkout. Preserve
other branches and all previous evidence.
